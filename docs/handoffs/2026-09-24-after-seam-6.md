## What seam 6 found

- **`nextReady` really did disagree, and it was live, not hypothetical.**
  `run-queue.sh`'s own `next_ready` skipped `TEMPLATE.md`; `launch.ts`'s
  private `nextReady` (built on `storyFiles()`, a deliberate copy of the
  bash launcher's original, non-skipping glob) did not. Khaita's real
  `TEMPLATE.md` carries `status: ready` in its own frontmatter — the
  placeholder text, never edited. A bare `launch.sh <repo>` (no id — a
  human testing something by hand; the queue and the bot always pass an
  id) picked `TEMPLATE` and ran the full pipeline against it, leaving it
  `needs_human` with a builder's mutations in its frontmatter. Case 128
  proved it red against real `launch.ts`. Fixed by moving the choice into
  `status.ts`'s `nextReady` (built on the already-`TEMPLATE`-excluding
  `storyIds`), and pointing both the launcher and the queue at it. L-30.
- **Two parity gaps, found only by the old-vs-new diff** — no test-lib
  case happened to assert either one's absence: `run-queue.sh`'s
  `LOG_TAG=queue` prefixes every one of the queue's own log/warn lines
  `[queue] ` (not the lines a child `launch.sh`/`merge.sh` process prints
  itself — an unexported bash variable); `refresh_from_origin`'s merge only
  redirects stderr, so git's own stdout (`Already up to date.`) reached the
  log. Both fixed; see the seam-6 record for detail.
- **A no-op scrape dropped.** `run-queue.sh:138` computed `$reasons` from
  the review file and never read it. Not ported.
- **Each story still runs as a separate process**, per the plan's own
  decision going in: `runQueue` shells to `bash launch.sh`/`bash merge.sh`
  with a new `runInherit` primitive (`lib/proc.ts` — stdio fully inherited,
  unlike `runSync`, which always captures stdout, or `runToFile`, which
  redirects to a log file). `--all` still re-execs the bash wrapper once
  per registered repo. Neither `launch()` nor `merge()` is called
  in-process from the queue.

## Rules that held today and hold tomorrow

Work in a worktree, never in `~/work/fleet` while the timers run. Run the
suite on a snapshot or a settled worktree, never mid-edit: `test-lib.sh`
sources itself with `exec env -i … bash "$0" "$@"` at the top for a clean
environment — sourcing it directly (as a parity script's fixture helper)
needs `FLEET_TEST_CLEAN=1` set first to skip that re-exec, or it silently
replaces the calling shell's whole process image. One task, one commit,
suite green before each — a case whose fix isn't landed yet cannot be
committed alone (case 128's test and its `nextReady` fix went in together
for exactly this reason). Land through a PR the human merges. Never start
a launcher or the queue as a child of the session. Kill by cwd, never
`pkill -f`.
