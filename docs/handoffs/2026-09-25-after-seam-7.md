## What seam 7 found

Nothing like seam 6's `TEMPLATE.md` bug — this was a faithful, mechanical
port. Cases 39, 94, 98 and 116 (lint-story: shape, citations, epic-base
resolution, the model alias check including haiku's rejection) and 94
(new-epic: creation and every refusal) all pass **unmodified** against the
TS binaries; no case needed a wording change. Two design choices worth
knowing about if you touch this code:

- **`write-story.ts` calls `lint-story.ts` in-process**, not a shell-out.
  Seam 6 kept the queue's shell-out to `launch.sh`/`merge.sh` on purpose —
  it isolates a *builder or reviewer* run's memory and any `Die` from the
  rest of a drain. Neither risk exists between write-story and a lint of
  the file it just wrote, so there was no reason to pay for a second
  process here.
- **`write-story`'s `claude -p` call has no timeout.** The bash never
  wrapped it in `timeout`, unlike the launcher's builder/reviewer calls — a
  human runs `write-story.sh` by hand and is watching. The port's `run()`
  call uses `timeoutSec: 0`, which `lib/proc.ts` already treats as "no
  timeout" (the same contract `timeout 0` had). `runBuilder`/`builderArgv`
  from `lib/agents.ts` weren't reusable as-is for the call itself —
  `runBuilder`'s parameter type doesn't include `allowedTools`, and an
  object literal with it fails TypeScript's excess-property check even
  though `builderArgv` itself accepts it — so `write-story.ts` calls `run`
  and `builderArgv` directly rather than widening a shared type for one
  caller's default.

`test/claude` gained a new mode, `FAKE_BUILDER=story` (writes
`.stories/$FAKE_STORY_ID.md`, dying loudly if `TEMPLATE.md` isn't in the
worktree first — the postcondition the port's own `writeStory` also
checks), and `FAKE_STORY_NOAC=1` to make it write a story that fails lint.
Case 132 is the first end-to-end characterization write-story.sh ever had
(case 94 only covered `--base` validation).

## The next session: seam 8, `telegram.sh`

Per `docs/plans/2026-09-23-typescript-migration.md`'s seam list: the hard
part is testing, not the port. `telegram.sh`'s `curl` is faked on PATH the
same way `claude`/`codex` are — but Node's `fetch` doesn't go through PATH,
so nothing in today's suite can intercept a TS port's HTTP calls the way
`test/claude` intercepts agent calls. The suite needs a new seam first — an
API base URL the fake can point `fetch` at (a local test server, or an
injectable base URL fixture) — before any `telegram.sh` line moves.
`flock` becomes `lock.ts` (already exists — `ts/src/lib/lock.ts`, used by
the launcher since seam 4; telegram.sh's own flock usage is what still
needs porting).

Small, unrelated to telegram.sh, and doable any time: `install-skills.sh`,
`update-agents.sh`, the remaining wrapper scripts — none of them need the
fetch-interception seam.

## Rules that held today and hold tomorrow

Work in a worktree, never in `~/work/fleet` while the timers run. One task,
one commit, suite green before each. A case is characterized before the
port, not invented after — for a faithful port with no behavior change (as
this whole seam was), "characterized" can mean "the existing case already
covers it and passes unmodified," which is itself the proof; a genuinely
new path (write-story's full happy path, here) still needs its own case,
seen passing against the bash first and then, unmodified, against the
port. A parity diff that has never been observed to catch a real
difference is not a proof of anything — check it against a deliberately
wrong build before trusting a clean run. Land through a PR the human
merges. Never start a launcher, the queue, or a live write-story/new-epic
run against a real target from this session — `write-story.sh` and
`new-epic.sh` push branches and spawn a real agent call if run unfaked;
`lint-story.sh <repo> <id> --strict` is the one genuinely read-only smoke
test available against a real target.
