## What seam 5 found

- **Two latent bugs in the bash**, fixed in the port and pinned (L-29):
  `merge.sh` wrote the merge log before `mkdir -p .runs`, `revert.sh` never
  made `.runs/`; on a checkout without it a clean merge read as a conflict.
  A khaita `--epic` merge from a fresh clone would have hit this.
- **`--land` with the base checked out leaves the record diverged.** Case
  120c pins what the bash does and the port reproduces: `merge.sh <id>
  --land` pushes the merge to `origin/<base>`, warns `local <base> is checked
  out — run: git pull --ff-only`, then commits the `merged:` record on the
  local base — which is now behind origin — and its push is refused (`push
  failed — the record is local only`). The human's `git pull --ff-only`
  then fails: the branches have diverged. In khaita the checkout is on
  `develop`, so every `/merge khaita <id>` (a develop story) ends this way.
  `--epic` is unaffected (nothing recorded). Deliberately not part of the
  parity port; **fixed right after it** (branch `land-record`): a clean
  checkout on the base is fast-forwarded to the merge before the record,
  case 120c; a dirty one keeps the warning, case 120d.
- **Nothing calls `reset.sh`**; it is documented for humans only.
